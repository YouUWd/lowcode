# 低代码平台：模块设计页面交互设计规范 (UI/UX Spec)

本规范为低代码设计端（建模画布）的页面布局、组件交互以及与后端元数据模型（`ModuleMeta`）的双向绑定提供设计指南，旨在保障设计师能以可视化的方式高效完成物理模型构建。

---

## 🎨 一、 经典三栏式布局设计 (Layout Blueprint)

推荐采用主流 SaaS 及低代码平台的 **“左导航大纲、中画布工作区、右属性配置面板”** 的三栏式经典结构：

```
+----------------------------------------------------------------------------------+
|                     顶部工具栏 (保存、刷新缓存、退出、导入/导出)                  |
+----------------------------------------------------------------------------------+
|            |                                                     |               |
|  左侧面板  |                 中间画布工作区 (Canvas)             |   右侧面板    |
|            |                                                     |               |
|  [组件库]  |  +-----------------------------------------------+  |  [属性面板]   |
|  - MAIN表  |  |  主表: orders (MAIN)                          |  |               |
|  - SUB表   |  |  +-----------------------------------------+  |  |  当前选中：   |
|  - JOIN表  |  |  | 列名       | 标签   | 数据类型 | 操作     |  |  orders.remark|
|            |  |  +------------+--------+----------+--------+  |  |               |
|  [表树大纲]|  |  | id         | 编号   | BIGINT   | [编辑] |  |  - 显示标签： |
|  - orders  |  |  | order_no   | 订单号 | VARCHAR  | [编辑] |  |    [ 订单备注]|
|  - items   |  |  +------------+--------+----------+--------+  |  - 可查询：[x]|
|  - profile |  +-----------------------------------------------+  |  - 可排序：[ ]|
|            |                                                     |  - 可写入：[x]|
+----------------------------------------------------------------------------------+
```

### 1. 左侧面板：元数据大纲与组件库 (Schema Explorer)
* **组件库**：支持拖拽或快捷按钮添加三类物理表（`MAIN`、`SUB`、`JOIN`）及多对多关联（`RELATION`）。
* **表树大纲**：以树状多层结构渲染当前模块中已经配置的表（如主表下挂载子表、JOIN关联表以及多对多表关系树），点击节点可快速定位中间画布并打开右侧属性面板。

### 2. 中间画布：字段配置与布局工作区 (Visual Canvas)
* 以**结构卡片 (Card)** 承载各个表。主表（`MAIN`）置顶且不可删除，从表（`SUB`）和拍平表（`JOIN`）以从属卡片紧随其后。
* 卡片内以**明细列表 (Table)** 形式平铺展示所有已选中的物理列。
* 支持拖拽行（Drag Handle）进行字段在页面中渲染顺序（`sort_order`）的调整。

### 3. 右侧面板：属性检查器 (Property Inspector)
* 全局响应式。当在中间画布或左侧大纲中选中不同的“表”、“字段”或“关联”时，右侧自动切换展示其属性输入表单。

## ⚡ 二、 核心交互工作流与元数据双向绑定 (Interaction Workflows)

### 1. 添加物理表与 query_type 设定

* **交互流程**：
  1. 设计师点击“添加表”，弹窗拉取当前数据库中所有尚未加入该模块的**物理基础表**清单。
  2. 选中表后，必须选择其在低代码模型中的角色（`query_type`）：
     * **设为从表 (`SUB`)**：需指定**外键关联列 (`foreignKey`)**，如指定 `order_id` 关联 `orders.id`。
     * **设为关联表 (`JOIN`)**：需设定 **JOIN 关联条件 (`joinOn`)**（如 `orders.customer = customer_profiles.name`）以及默认的 **`joinType`**（默认 `LEFT`）。
  3. 点击确认后，画布中生成对应的表卡片。

---

### 2. 字段白名单选取与展示重命名 (字段设计)

在表卡片中，字段的配置是设计的核心：

* **白名单选取（勾选框）**：
  * 卡片右上角提供“选取字段”按钮，点击打开抽屉，列出该物理表在数据库中的所有真实列。
  * 勾选需要的列（即加入 `fields` 白名单），未勾选的物理列将不会返回给前端，从而实现底层数据安全。
* **展示名称重命名 (`label` 绑定)**：
  * 画布表格上列出已选字段的“物理列名 (columnName)”与“展示标签 (label)”。
  * 设计师可以直接双击 `label` 单元格进行就地编辑（In-place Edit），将 `order_no` 修改为“订单号”，该修改将直接双向绑定修改 `FieldMeta` 中的 `label` 属性。
* **查询操作符设定**：
  * 在面板中直接为该字段选择对应的**过滤操作符 (`queryOp`)**，如下拉选择 `EQ`、`LIKE`、`GT`。系统不再强制约束可查询/可排序/可写开关，任何物理列都按实际业务需求或角色权限进行通用读写和排序。

---

### 3. 建立 N:M 多对多关联 (Relation Builder)

当需要将主表与另一个不含直接外键的表建立多对多关系（如订单与标签）时：

* **交互流程**：
  1. 点击“新建多对多关联”，在连线弹窗中选择：
     * **左表 (Left Table)**：默认为主表（`orders`）。
     * **右表 (Right Table)**：选择目标关联物理表（如 `tags`）。
     * **中间表 (Junction Table)**：选择数据库里的多对多关联表（如 `order_tag_relation`）。
     * **外键映射**：选择中间表中指向左表的外键列（`left_fk`）与指向右表的外键列（`right_fk`）。
  2. 命名该关联名（如 `tags`），此名称将直接作为运行时 JSON 查询/保存的嵌套 Key。

## 🛡️ 三、 防呆与安全防护设计 (Failsafe & Defensive UX)

低代码引擎在后台有一套极度严格的结构校验体系。为了防止用户在前台胡乱配置导致后端保存失败，前端必须做强交互防御：

### 1. 主表防删机制
* 画布中的 `MAIN` 类型表（主表）有且仅能有一个，界面应隐藏其删除按钮。

### 2. 字段类型安全锁定
* 物理字段的 `columnName`（列名）和 `dataType`（数据类型，如 BIGINT、DATETIME）是从数据库表 Schema 中读取的，**前端仅提供展示，绝对不允许用户手动编辑文本**，避免数据入库失败。

### 3. 字段级权限自动清空警告 (破坏性操作提示)
* **交互防呆**：若设计师在画布中**删除**了某个表或某些字段（点击卡片垃圾桶按钮），前端应弹出二次红色警告：
  > ⚠️ **警告**：删除该字段元数据，将导致所有配置过此字段的角色权限（如 editor、viewer 的只读/修改权限）在保存后被**物理清空并永久丢失**！请确认是否继续？

### 4. 提交校验逻辑 (Client-side Validation)
在用户点击顶部“保存设计”按钮时，前端在发送 `POST /api/module/design` 之前进行本地快速扫描校验：
1. **是否存在 MAIN 表**：若无，阻断并提示“必须设定一个主表”。
2. **SUB 类型表外键完整性**：若从表的 `foreignKey` 为空，标红其卡片并提示“请指定从表关联主表的外键字段”。
3. **JOIN 类型表条件完整性**：若拍平表的 `joinOn` 条件公式为空，阻断并提示“请填写 LEFT JOIN 条件”。

## 🔄 四、 极速体验优化 (Quality-of-Life Upgrades)

1. **缓存一键刷新**：
   * 顶部工具栏设计“刷新缓存”按钮，点击后调用 `POST /api/module/{moduleId}/refresh-cache`。并在操作成功后弹出气泡提示：“刷新成功，新模型配置已实时生效于数据接口”。
2. **预览运行效果**：
   * 工具栏提供“预览”切换按钮。点击后弹窗展示一个“数据表格+增删改表单”的真实运行态页面，以便设计师能够以特定角色（通过 Header `X-Role` 切换）直接模拟查询、创建和修改，即时体验权限控制与布局效果，无需发布上线。
